## 0. このメモの位置づけ

管理者が監査ログを閲覧する専用画面を新設する。
既存の管理画面(`admin.html` / `list.html` / `announce.html` / `markets.html` /
`minutes.html` / `members.html`)と同じ位置づけのモックで、**HTML+CSS+バニラJS、
ダミーデータ**で作る。フレームワーク不使用(既存モックの流儀を踏襲すること)。

この画面は**モックが存在しない唯一の管理画面**だったため、他画面と同じ
「モック確認・承認 → 実装」の流れに乗せるために先行して作る。

## 1. 作るもの

### 1-1. `logs.html`(新規)

管理者のみがアクセスする操作ログ閲覧画面。

**データ構造は親子2階層**(実装時の `audit_events` / `audit_details` に対応)。

- **一覧は親のみ表示**。1操作=1行
- **行をタップすると子明細が展開**(アコーディオン)。閉じると畳む
- 複数行を同時に開けてよい

#### 一覧の表示列

| 列 | 内容 | 備考 |
|---|---|---|
| 日時 | `2026-08-24 14:32` | JST |
| 操作者 | 氏名 | 名簿の氏名。ログイン失敗などは「(不明)」 |
| 種別 | バッジ表示 | 下記の色分け |
| 概要 | 1行サマリ | 例「8/24 個人選果 32セル確定」 |
| 明細 | 件数 | 0件の場合は展開不可(タップしても開かない) |

- **システム管理者による操作**には行末に専用バッジ「システム管理者」を付ける
  (`by_system_admin = 1` に対応。目立つ色で)
- 50件ずつページ分割(`list.html` と同じ方式・同じ見た目に揃える)
- 日付降順が既定

#### 種別バッジの色分け

| 種別 | 表示名 | 色の方向性 |
|---|---|---|
| `login_ok` / `login_ng` | ログイン / ログイン失敗 | 失敗は赤系 |
| `fact_save` / `fact_confirm` | データ入力 / データ確定 | 青系 |
| `announce_post` / `announce_revise` / `announce_withdraw` / `announce_republish` / `announce_delete` | お知らせ関連 | 緑系。`withdraw`・`delete` は赤系 |
| `minutes_change` | 議事録 | 紫系 |
| `master_change` | マスタ変更 | グレー系 |
| `member_change` | 名簿変更 | オレンジ系 |
| `axis_migration` | 軸の移行 | グレー系 |

配色は既存モックの CSS 変数を流用し、新しい色を増やしすぎないこと。

#### 展開したときの子明細

テーブルで表示する。

| 列 | 内容 |
|---|---|
| 対象 | 「東京市場 / 2L」のように人が読める形 |
| 項目 | 単価 / 数量 / 本文 など |
| 変更前 | 空欄なら「(なし)」 |
| 変更後 | |

- 変更前→変更後は **→ の矢印**で視覚的に繋ぐ
- 本文のような長いテキストは3行で折りたたみ、「全文を見る」で展開

#### 絞り込み

画面上部に配置。既存モックのフィルタUIの見た目に揃える。

- **期間**:開始日・終了日のプルダウン(`list.html` と同じ方式。曜日表記・土日祝の色分けも同じ)
- **操作種別**:チェックボックス(ログイン / データ / お知らせ / 議事録 / マスタ / 名簿)
  ※ 個別イベント名ではなく**グループ単位**で選ばせる。全選択/全解除ボタン付き
- **操作者**:プルダウン(名簿から。「すべて」既定)
- **市場**:チェックボックス(7市場。全選択/全解除付き)
  ※ 実装時は「明細 → 実績 → 組み合わせ → 軸値」のJOINで実現する。
  モックではダミーデータをJS側でフィルタするだけでよい
- **キーワード**:概要を対象としたテキスト検索

絞り込み中は「該当 xx件」を件数表示する。

#### 空状態

該当0件のときは「条件に一致する操作ログはありません」と中央に表示。

### 1-2. 全ページの管理者用ナビ帯を7項目に更新

既存の管理者用ナビ帯(6項目)に **「操作ログ」** を追加する。

```
データ入力 / データ一覧 / お知らせ投稿 / 市場の管理 / 議事録 / 部会員名簿 / 操作ログ
```

- **管理者用ナビ帯を持つ全ページで更新すること**(admin.html / list.html /
  announce.html / markets.html / minutes.html / minutes-detail.html /
  minutes-edit.html / members.html / logs.html)
- 一般ユーザー用ナビ帯は**変更しない**(ダッシュボード / データ一覧 / 議事録 の3項目のまま)
- 管理者用ナビ帯は**一般ユーザーには帯ごと非表示**(既存ルールを維持)
- スマホ幅では横スクロールのピル形式(既存の挙動をそのまま使う。7項目でも
  破綻しないことを実機幅で確認すること)
- 現在開いているページはハイライトして非活性(既存ルール)

### 1-3. ダミーデータ

`logs.html` 内に JS の配列としてベタ書きでよい(既存モックの流儀に合わせる)。

- **60〜80件程度**用意する(ページ分割の挙動が確認できる量)
- 期間は直近2ヶ月程度に散らす
- **全種別を最低1件ずつ含める**こと。特に以下は必ず入れる:
  - `login_ng`(ログイン失敗)
  - `announce_withdraw` → `announce_republish` の一連の流れ
  - `announce_delete`
  - `fact_save` で明細が20件以上あるもの(展開時の見た目確認用)
  - `by_system_admin = 1` のもの
  - 明細0件のもの(展開不可の確認用)

## 実装メモ(作業結果)

- `logs.html` を新規作成。列構成・絞り込み(期間/操作種別/操作者/市場/キーワード)・
  50件ページ分割・アコーディオン展開・長文3行折りたたみをすべて実装。
- ダミーデータは70件(手動シナリオ20件+機械生成50件)。全18種別を最低1件含み、
  本体・追補で指定された必須シナリオ(ログイン失敗・お知らせ取り下げ→再掲載・
  お知らせ削除・20件超の明細を持つfact_save・システム管理者操作・明細0件・
  お知らせ投稿→LINE共有・議事録取り下げ→再反映・LINE連携解除に伴う
  session_revoke+member_changeのセット)をすべて含めた。
- 種別バッジの配色は既存CSS変数(`--vine-deep`/`--hol`/`--sat`/`--warn-bg` 等)と
  `announce.html` の `.badge.cat-*` で使われている紫・グレーの配色をそのまま流用。
  新規の色は「システム管理者」バッジ(`--tomato` の単色塗り)のみ。
- `assets/nav.js` の `NAV_ADMIN` 配列に「操作ログ」を1箇所追加。共有スクリプトのため
  対象9ページすべてに自動反映(各ページ個別の編集は不要だった)。
- Playwright(既存の devDependency)でヘッドレス動作確認:
  - 70件・2ページの表示、絞り込み適用、アコーディオン開閉、長文展開/折りたたみ
  - 375px幅での横スクロール発生なし(既存8ページ+logs.htmlすべて確認)
  - JSエラーなし
