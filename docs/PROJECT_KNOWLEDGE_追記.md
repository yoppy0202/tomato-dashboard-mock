差し替え後:

```
### 画面共通のルール(確定)
- 各画面からの戻りリンクは**「← TOPへ戻る」で統一**(ページごとに文言を変えない)

#### サイト内ナビゲーション(確定)
ダッシュボードを起点とした放射状構造(各ページは「TOPへ戻る」しか持たない)を改め、
**共通ナビゲーション帯**で関連ページを相互に行き来できるようにする。
管理者が入力→お知らせ投稿→市場管理と作業をまたぐたびにTOPを経由する手間を無くすため。

- **管理者用ナビ帯**(管理者ログイン時のみ表示):
  データ入力(`admin.html`)/ データ一覧(`list.html`)/ お知らせ投稿(`announce.html`)/
  市場の管理(`markets.html`)/ 議事録(`minutes.html`)の5ページを相互リンク
- **一般ユーザー用ナビ帯**(全員に表示):
  ダッシュボード(`index.html`)/ データ一覧(`list.html`)/ 議事録(`minutes.html`)の3ページを相互リンク
  - 個別お知らせはダッシュボードの「お知らせ」欄から遷移する形を維持(ナビ項目には入れない)
- ナビ帯は各ページ上部に常時表示。**現在開いているページはハイライトして非活性**(自分自身へのリンクは無効化)
- 表示形態:PC/タブレットは横並び、スマホ幅では横スクロールのピル形式に切替
- 管理者用ナビ帯は**一般ユーザーには帯ごと非表示**(存在を見せない。議事録の役員協議会タブと同じ考え方)
- `admin.html`の既存「管理モード」帯を拡張してナビ帯を兼ねさせる(帯を二重に出さない)

#### 未保存離脱ガード(確定)
入力途中で他ページへ移動して入力内容を失う事故を防ぐため、**全入力画面に共通の離脱ガード**を入れる。

- 対象画面:`admin.html`(マトリクス入力)、`announce.html`(お知らせ下書き)、
  `markets.html`(並べ替え・追加)、`minutes.html`(議事録の投稿・編集)
- 「未保存の変更があるか」をフラグで管理(入力変更時にON、保存完了時にOFF)
- フラグONの状態で以下が発生したら警告:
  1. 共通ナビ帯のリンククリック → **サイト内確認ダイアログ**で遷移を止める
  2. 「← TOPへ戻る」クリック → 同上
  3. ブラウザの戻る/更新/タブを閉じる → **`beforeunload`によるブラウザ標準の確認**
     (文言はブラウザ依存で変更不可のため、サイト内ダイアログとは別扱いとする)
- サイト内ダイアログの選択肢は3つ:
  - 「保存してから離れる」…その画面の保存処理を呼び出し、完了後に遷移
    (下書き保存で足りる画面は下書き保存。`admin.html`のように確定フローがある画面は確定フローに合流させる)
  - 「このまま離れる」…変更を破棄して遷移(赤字表記)
  - 「キャンセル(このページに留まる)」
```

- **一般ユーザー**:従来どおり**集計数(x/40人)のみ**表示。個人単位の内訳は見せない
  (誰が読んでいないかを部会員同士で見せ合う必要はないため、内訳は管理者限定)
- 議事録にも同じ既読記録の仕組みを流用できる構造にしておく(将来の展開余地を残す)
- **未読者へのLINE個別リマインド送信はフェーズ1では実装しない**(→ §10 保留案件)

## 【挿入3】新規セクションとして §7 の直後に追加(以降のセクション番号を繰り下げ)

```
## 8. 議事録機能

部会の議事録をサイト上で共有・検索できるようにする。

### カテゴリと閲覧権限(確定)
- カテゴリは**「役員協議会」「全体協議会」**の2種。カテゴリはマスタ管理とし、追加時も画面改修なしで対応
- **管理者**:両カテゴリの閲覧・投稿・編集・削除(論理削除)
- **一般ユーザー**:**全体協議会のみ閲覧**(投稿・編集・コメント等は不可)
- 一般ユーザーには**役員協議会をタブごと非表示**にする
  (件数表示や「権限がありません」表示も出さず、存在自体を見せない)
- お知らせのカテゴリ(全体/個人選果/共同選果)が「表示上の目印」なのに対し、
  議事録のカテゴリは**実際のアクセス制御**である点が異なる。実装時に混同しないこと

### 本文と添付ファイル(確定)
- **本文はテキスト入力**(管理画面から直接入力・編集)。検索対象はこの本文とタイトル
- **添付ファイル**(PDF/Word)を任意で複数添付可。原本保管・配布資料用
  - 保存先は**VPS上のサーバーディレクトリ**(DBにはファイルパスとメタ情報のみ保持)
  - バックアップ対象に含める(`age`暗号化バックアップの対象を DB＋添付ディレクトリに拡張)
  - **フェーズ1では添付ファイルの中身は検索対象外**(PDF内テキスト検索は実装コストが見合わないため)

### 一覧画面(確定)
- 日付降順。カテゴリバッジ・日付・タイトル・本文冒頭・添付有無を表示
- カテゴリタブ(すべて / 全体協議会 / 役員協議会)で絞り込み
- 一般ユーザーには役員協議会タブが表示されず、一覧にも役員協議会の議事録は出ない

### 詳細画面(確定)
- カテゴリバッジ・日付・タイトル・投稿者・最終更新日時・本文・添付ファイル一覧
- 添付ファイルはアイコン付きリストで表示し、タップでダウンロード
- **管理者にのみ「編集」「削除」ボタンを表示**(閲覧用・管理用に画面を二重に作らない。§3の方針を踏襲)

### 検索(確定)
- キーワード検索:**タイトル＋本文**を対象
- 絞り込み:カテゴリ、日付範囲
- **検索処理そのものに権限フィルタをかける**。一般ユーザーの検索結果には
  役員協議会の議事録が一切ヒットしない(画面側で隠すのではなく、クエリ段階で除外する)

### 監査ログ
- 議事録の投稿・編集・削除を監査ログに記録
- ログには議事録IDを持たせ、**議事録単位での絞り込み**を可能にする
  (市場マスタの変更ログと同じ方式。→ §1 データ整合性の原則)
```

## 【挿入4】§10「検討したが不採用/保留になった案」に追加

```
- **未読者へのLINE個別リマインド送信**:フェーズ1では保留。
  LINE公式アカウント無料プランは月200通までのため、個別リマインドを頻発させると
  お知らせ配信の枠を圧迫する。まずは未読者の一覧表示のみを提供し、
  フォローアップの手段は管理者の判断に委ねる。実需が出てから実装判断する
  (OCRと同じ二段構えの考え方)
- **議事録の添付ファイル内テキスト検索**:フェーズ1では対象外。
  本文テキストでの検索が機能していれば実用上足りるという判断。
  必要になればPDFのテキスト抽出を後付けする
```
