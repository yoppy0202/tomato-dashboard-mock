## 【挿入F】§3「ログイン方式と権限」の「### ログイン」を差し替え

差し替え後:

```
### ログイン
- **LINEログイン**を採用(SMS認証は不採用。コストと導入ハードルの両面でLINEが優位という結論)
- 流れ:①「LINEでログイン」を選択 → ②LINEアプリで同意 → ③初回のみ部会員名簿と紐付け → ④以降は自動ログイン

#### 名簿とLINEアカウントの紐付け(確定)
LINEログインで取得できるのはLINE側の内部ID(`userId`)と表示名のみで、
「その人が部会員の誰なのか」はシステム側では判別できない。
表示名はニックネームのことが多く、氏名との突合にも使えないため、初回に明示的な紐付けを行う。

**方式:管理者が先に名簿を登録 → 初回ログイン時に本人が名簿から自分を選択**

1. 管理者が名簿管理画面(`members.html`)で部会員の氏名を事前登録(部会の名簿から転記)
2. 部会員が初回ログイン → 「あなたのお名前を選んでください」と名簿一覧を表示
3. 本人が自分の氏名を選択 → LINEの`userId`と名簿レコードを紐付け
4. 管理者は名簿管理画面で「連携済み / 未連携」を随時確認できる

- 本人に氏名を入力させる方式(→ §11 不採用案)ではなく**選択方式**とする理由:
  表記ゆれが発生せず、ITリテラシーが高くない利用者でも確実に完了できるため
- **氏名は名簿側の値を正**とし、LINEの表示名は紐付け時の参照にのみ使う。
  議事録の投稿者名・既読/未読の氏名一覧など、画面表示はすべて名簿の氏名を使用する
- 機種変更等でLINEアカウントが変わった場合に備え、管理者が**連携解除**して再紐付けできるようにする
```

- 画面には「一覧から外しても過去の記録は消えない」旨を常時表示する
- 管理者用ナビ帯に6つ目の項目として追加する(→ §2 サイト内ナビゲーション)

## 【挿入H】§8「議事録機能」の「### 本文と添付ファイル(確定)」を差し替え

差し替え後:

```
### 本文と添付ファイル(確定)
- **本文はテキスト入力**(管理画面から直接入力・編集)。検索対象はこの本文とタイトル
- **添付ファイル**を任意で複数添付可。原本保管・配布資料用
  - 保存先は**VPS上のサーバーディレクトリ**(DBにはファイルパスとメタ情報のみ保持)
  - バックアップ対象に含める(`age`暗号化バックアップの対象を DB＋添付ディレクトリに拡張。
    **DBダンプと同じcronにまとめる**。別建てにすると片方だけ失敗した際に気づきにくく、
    復元時のタイミングもずれるため)
  - **フェーズ1では添付ファイルの中身は検索対象外**(PDF内テキスト検索は実装コストが見合わないため)

#### 許可形式と容量(確定)
- **許可する拡張子**:PDF / Word(.docx .doc)/ Excel(.xlsx .xls)/ PowerPoint(.pptx .ppt)/
  画像(.jpg .jpeg .png .heic)
- **許可しない**:実行ファイル・スクリプト(.exe .bat .js .html 等)、圧縮ファイル(.zip 等)、動画
  - 実行ファイル・スクリプトは、マルウェアや偽ページの配布経路になり得るため
    (お知らせのURLに対するSafe Browsingチェック〈→ §7〉が添付経由で素通りされる)
  - 圧縮ファイルは展開するまで中身を検査できないため
  - 動画は容量とバックアップ負荷が大きいため。必要な場合はLINEグループへの直接投稿で代替
  - なお議事録を投稿できるのは管理者のみのため、不特定多数のアップロードに比べリスクは低い。
    その前提で画像・PowerPointまで許可範囲を広げている
- **容量上限**:1ファイル20MB / 1議事録あたり最大10ファイル

#### 画像の自動圧縮(確定)
容量を圧迫する主因は写真であるため、**画像のみサーバー側で自動圧縮**する。

- アップロード時に長辺を一定サイズへリサイズし、再エンコードして保存
- **HEICはJPEGへ変換**(閲覧互換性の確保も兼ねる)
- **PDF・Officeファイルは圧縮せず原本のまま保存**する
  - PDFの再圧縮はスキャン文書の可読性を損なうリスクがあるため
  - Officeファイルは内部が既にzip圧縮されており、再圧縮の効果がほぼないため
- 圧縮は不可逆であり、圧縮後のファイルが原本となる。原本を別途保持する二重管理は行わない
  (容量削減という目的と矛盾するため)
```

## 【挿入I】§11「検討したが不採用/保留になった案」に追加

```
- **紐付け時に本人へ氏名を入力させる方式**:表記ゆれ(「山田太郎」「山田 太郎」)が発生すること、
  管理者の承認作業が導入時に40件発生すること、承認待ちの滞留が問い合わせを招くことから不採用。

  許可リスト方式とする(→ §8 許可形式と容量)
- **添付PDFの自動圧縮**:スキャン文書の可読性を損なうリスクがあるため見送り。画像のみ圧縮する
```
