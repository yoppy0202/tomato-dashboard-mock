# 実装指示メモ:CSV案内文の追加＋資料用スクリーンショットの自動取得

対象リポジトリ:`yoppy0202/tomato-dashboard-mock`
作業ディレクトリ:`/mnt/c/dev/tomato-dashboard-mock`

作業は2部構成。**まず1(実装)を終えてコミット・デプロイし、その後に2(キャプチャ)を実行すること。**
先にキャプチャを撮ると案内文が写らないため、順序を守る。

---

# 1. CSVダウンロードの案内文を追加(`list.html`)

CSV出力はスマホでもダウンロード自体は可能だが、端末に表計算アプリが無いと開けない。
ITリテラシーが高くない利用者がつまずくポイントのため、ボタン付近に案内を出す。

- CSV出力ボタンの直下(またはすぐ近く)に、以下の趣旨の注記を常時表示する
  - 表計算アプリ(Excel・Googleスプレッドシート等)で開く前提であること
  - **PC/タブレットでの利用を推奨**すること
  - スマホでもダウンロードは可能だが、表計算アプリが必要になること
- 文言は既存ページのトーン(です・ます調、簡潔)に合わせる。警告色ではなく補足情報として控えめに出す
- 実装後、コミット・プッシュ・GitHub Pagesへのデプロイまで行う
  - デプロイが10分以上停止した場合は、実行をキャンセルのうえ`git commit --allow-empty`で再実行してよい

# 2. 資料用スクリーンショットの自動取得

部会向けの操作説明資料(PDF)に貼る画像を用意する。

## 2-1. 環境

- **Playwright**(Node版・Chromium)を使用
- 撮影対象は**GitHub Pages上の公開URL**(`https://yoppy0202.github.io/tomato-dashboard-mock/`)。
  デプロイ完了を確認してから実行すること
- スクリプトは `scripts/capture.js` として作成し、リポジトリにコミットする
  (画面変更のたびに撮り直せるようにするため)
- Playwright本体とブラウザバイナリは `node_modules` / キャッシュに入るため、
  `.gitignore` を確認し、リポジトリに巨大なバイナリが入らないようにすること

## 2-2. 撮影条件

- **画面幅はすべてスマホ幅**(390×844、deviceScaleFactor 2 程度)で統一
- 役割(一般/管理者)は`localStorage`で保持しているため、
  ページ読み込み前に`localStorage`へ役割をセットしてからナビゲートすること
- 各ページは読み込み後に少し待機し、グラフ・動的要素の描画完了を待つ
- 出力先は `docs/screenshots/` 配下。ファイル名は下表のとおり

## 2-4. 完了報告

- 撮影した16枚のファイル名と、それぞれ何が写っているかを簡潔に報告する
- 意図した要素が撮れていないものがあれば、その旨を明記する
  (資料側で差し替え・再撮影の判断をするため)
- `scripts/capture.js` と `docs/screenshots/` をコミット・プッシュする

# 3. 注意事項

- 今回の資料は**モック(ダミーデータ)版の暫定資料**という位置づけ。
  本番稼働後に撮り直す前提のため、ダミーデータのままで問題ない
- 撮影中に`localStorage`へテスト用の議事録・お知らせが溜まっている場合、
  実際の画面と異なる表示になる可能性がある。撮影前に`localStorage`をクリアし、
  初期のダミーデータ状態で撮ること
