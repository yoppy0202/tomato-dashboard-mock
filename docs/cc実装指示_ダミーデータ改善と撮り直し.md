# 1. ダミーの氏名を差し替え

現状、氏名のダミーデータが不自然で、資料に載せると目立つ。

- `announce.html` の既読/未読一覧が「田中 三郎」「田中 花子」「田中 恵子」…と**全員同じ姓**
- `members.html` の名簿が「山田 一郎」「山田 次郎」「山田 三郎」…と**全員同じ姓**、
  かつ `announce.html` 側と**姓が食い違っている**

### 対応
- 40名分の氏名を、**姓がばらけた自然な日本人名**で用意する
  (佐藤・鈴木・高橋・田中・伊藤・渡辺・山本・中村・小林・加藤 など一般的な姓を分散させる)
- **同じ40名のリストを `announce.html` と `members.html` で共有**すること
  - 既存の `assets/minutes-store.js` と同じ発想で、
    `assets/members-data.js` のような共有データファイルに切り出すのが望ましい
  - 既読/未読の内訳、名簿一覧、既読数(32/40人)、LINE連携済み数(34/40人)が
    同じ名簿を参照して整合するようにする
- ログイン中の管理者名(現在「山田」)も、この名簿内の実在する管理者名に揃える

# 2. 入力済み状態のダミーデータを用意

資料では「何をどう入力するか」が伝わる必要があるが、現状の撮影結果は入力欄が空で
機能の説明になっていない。

## 2-1. `admin.html`(マトリクス入力)
- スマホのアコーディオン表示で、**東京の5サイズすべてに単価・数量が入力済み**の状態を作れるようにする
- **kg換算が自動表示されている**こと(パック数÷5の結果が数量欄の下に出ている状態)
- 実現方法は問わない。以下のいずれかでよい:
  - URLパラメータ(例:`admin.html?demo=filled`)で入力済み状態を再現する
  - キャプチャスクリプト側でPlaywrightから値を入力してから撮影する
- **通常アクセス時のデフォルトは空欄のまま**にすること(実運用の動作を変えない)

## 2-2. `announce.html`(お知らせ投稿)
- 本文が入力済みで、**LINE配信プレビューに文面が反映されている**状態を作れるようにする
- 文字数カウンターも 0/500 ではなく実際の文字数が出ている状態
- 本文の例(そのまま使ってよい):
  「8/24(月)は集出荷場の空調点検のため、搬入受付を1時間繰り上げて7:00からとします。
  ご協力をお願いします。」
- こちらも通常アクセス時のデフォルトは空欄のままにすること
